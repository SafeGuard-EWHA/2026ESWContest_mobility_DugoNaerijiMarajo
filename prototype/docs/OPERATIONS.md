# 팀 Pi 운영 안내

## 접속 주소

**[대시보드 열기](https://safeguard.local:9443/dashboard)** · **[휴대폰 위치 전송](https://safeguard.local:8443/)** · [시작 화면·연결 코드](https://safeguard.local:9443/)

같은 네트워크의 Pi에 접속합니다. Pi 전원·네트워크·기기의 인증서 신뢰가 필요합니다. 웹 로그인과 휴대폰 연결 정보는 각각 7일이며 만료·사이트 데이터 삭제·연결 초기화 시 다시 인증합니다. 최초 휴대폰 등록은 시작 화면의 8자리 코드를 사용합니다. 위치 권한은 사용자가 허용하고, 매번 '시연 시작'을 눌러 화면을 켜 둡니다.

## 현재 가능한 일

Pi 전원 → 핫스팟 연결 → 웹 로그인 → 휴대폰 위치 전송 → 대시보드 위치·기상 외기온 확인. 웹·위치 서비스는 자동 시작하므로 PowerShell 명령어로 따로 실행하지 않습니다.

현재는 **접속 점검 모드**입니다. 실내 센서가 없으며 예측·출력이 비활성입니다. 센서나 ESP32를 꽂는 것만으로 실제 제어 모드로 전환되지는 않습니다.

## 처음 장치를 연결할 때

1. Pi를 끄고 기존 배선 계획에 맞게 ESP32·센서·출력 장치를 연결합니다.
2. Pi와 핫스팟을 켜고 휴대폰 위치를 전송합니다.
3. 실제 장치 경로·펌웨어·실내온도·UWB·탑승자 입력을 대조합니다. mmWave는 수리 완료 사용자 보고가 있으며 포트/검증 설정은 실물 입력을 확인해 반영합니다.
4. 실제 제어 서비스와 웹 프록시를 설정합니다. 시작 시 반드시 정지 유지(HELD) 및 ESP32 출력 OFF 보고를 확인합니다.
5. 센서 준비와 실내·외기 600초 이력 및 예측 유효 상태를 확인하고, 감시 재개·보호·전체 정지를 시험합니다. 버튼 활성화만으로 모든 센서와 모델이 준비됐다고 판단하지 않습니다.
6. 자동 시작을 활성화하고 재부팅 후 다시 정지 유지 → 감시 재개로 정상 감시에 들어가는지 검증합니다.

## 최초 설정 뒤 매번 사용할 순서

**Pi 전원 → 같은 네트워크 → 대시보드 → 휴대폰 위치 전송 시작 → 준비 상태 확인 → 감시 재개.**

네트워크/화면 재접속은 제어 메인을 재시작하지 않도록 분리합니다. 실제 메인·ESP32가 재시작되면 감시 재개가 다시 필요합니다. 화면을 새로고침하는 것과 유효한 온도 입력이 끊기는 것은 다릅니다. 위치 만료는 15초, 날씨 표본 최대 나이는 1800초이며 입력이 무효화되면 예측 이력을 다시 모아야 합니다. 선제 예측 시연 전에는 유효한 600초 이상 이력과 모델 준비를 확인합니다.

## 유지보수·배포 범위

- 팀 Pi 운영 폴더: `/home/pi/SafeGuard_Operational_20261031`. 기존 Main 및 촬영본은 보존합니다.
- 현재 `safeguard-navigation.service`, `safeguard-portal.service --connection-check`만 자동 시작합니다. main 및 전체 target의 활성화는 다음 실물 점검 단계입니다.
- 소스 복제, 서비스 설치, ESP32 펌웨어 업로드는 각각 별도입니다. GitHub 업로드가 Pi에 자동 배포되지는 않습니다.
- `../prepare_services.py`는 서비스 정의 생성용, `../stage_on_pi.py`는 기존 팀 Pi의 원본 해시·TLS를 확인하고 새 폴더에 빌드하는 준비용입니다. 장치를 새로 설치하는 범용 도구가 아닙니다. `baseline_main_sha256.json`은 10월 30일 팀 Pi 원본 기준이며 현재 GitHub 파일 해시가 아닙니다.
- 기존 설치된 위치 runner(`/usr/local/lib/safeguard-navigation`)와 인증서가 선행 조건입니다. 새 Pi에서는 네트워크·인증서·위치 수신 환경부터 별도 설정해야 합니다.
- [접속 전용 설치 기록](../maintenance/SafeGuard_Access_20261031/README.md)은 실제 사용한 고정 경로 도구를 보존합니다. 기존 서비스 파일이 있으면 중단하므로 현재 팀 Pi에 반복 실행하지 않습니다.
- 기존 인증서는 **2026-11-23 00:24:14 KST**에 만료됩니다. 이후 시연 전에 인증서 갱신·이름·기기 신뢰를 확인합니다. 현재는 `safeguard.local` 이름을 사용합니다.
- 인증 정보·TLS 개인키·현재 위치 JSON·실행 로그·빌드 결과는 공개 저장소에 올리지 않습니다.
