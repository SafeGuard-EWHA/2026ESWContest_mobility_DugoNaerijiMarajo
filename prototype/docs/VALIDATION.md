# 최신 검증

선제 보호 CMake/CTest 4개·대시보드·출력 경로·설치/롤백 검증은 [최신 검증 기록](../maintenance/SafeGuard_Predictive_Control_20261028/VALIDATION.md)을 참고하세요. 그래프 3종은 측정 CSV로 재생성하고 원본 88개 해시 보존을 확인했습니다. 아래는 이전 단계의 검증 이력입니다.

# 장치 제어 소스 검증 기록

최신 갱신 결과는 문서 하단의 열 추정 통합 항목입니다. 아래 초기 정리 기록은 당시 이력입니다.

검증일: 2026-10-28 KST. 작업 환경: 장치가 연결되지 않은 Linux 작업 공간.

| 항목 | 결과 |
|---|---|
| `python3 test_links.py` | 14개 모의 테스트 통과 |
| UWB 리더 `--self-test` | 파서, 신선도, 윈도 초기화, JSON 계약, 누락값 처리 통과 |
| Python 구문 컴파일 | 현재 메인 scripts 및 Software Stop 패키지 통과 |
| C++ 메인 직접 컴파일 | g++ / C++17 / `-Wall -Wextra -Wpedantic` 통과 |
| `test_core` 직접 컴파일·실행 | 통과 |
| `test_input` 직접 컴파일·실행 | 통과. 기존 테스트 집계 초기화에서 `stop_nonce` 누락 경고 1건 발생 |
| CMake 경로 | 작업 환경에 CMake가 없어 실행하지 못함. 동일 src를 g++로 직접 빌드해 확인 |
| 실제 장치 | 이번 정리 작업에서 새로 수행하지 않음. 사용자 관찰 결과는 STATUS.md 참고 |

펌웨어 전체 통합 테스트, 과거 maintenance 패키지 전체 테스트, 차량 실증 시험은 이번에 재실행하지 않았습니다. `test_links.py` 출력의 `FIRMWARE_OK`는 모의 데이터 테스트 출력이며 실제 보드 연결 증거가 아닙니다.

## 배포 전 확인

1. 팀원이 수정 중인 서보 코드와 현재 브랜치를 비교합니다.
2. Pi의 현재 파일과 비교합니다. 이 준비본은 실시간 Pi 전체 복사본이 아닙니다.
3. 실제 연결 장치의 USB 경로·위치 파일 경로·인증서·위치 수신 서비스 설정을 확인합니다.
4. 위험온도 35°C 복구, 서보 해결 여부, 전체 정지를 실제 장치에서 확인합니다.

## 파일 구성 검토

실행 산출물 디렉터리(runs/build/backups), 원시 JSONL 로그, Python 캐시, TLS 개인키·인증서 파일은 묶음에서 제외했습니다. 보관한 테스트의 좌표/토큰 리터럴은 합성 테스트 데이터이며 실제 운전 로그를 포함하지 않습니다. 기존 저장소의 공개 범위와 라이선스 파일은 변경하지 않았습니다.

## 열 추정 통합 갱신

현재 저장소 소스로 CMake Release 빌드 및 CTest 3개(core, input_contract_and_rearm, thermal_observer), 기존·연구용 대시보드 Node 렌더 테스트를 실행했습니다. 모두 통과했습니다. 기존 test_input의 stop_nonce 초기화 경고는 남아 있습니다.

추가 개발 검증(수치 검사, 7개 시나리오, 설치·롤백·미지원 소스 거부)과 문헌 기반 오차 분석은 [패키지 검증 기록](../maintenance/SafeGuard_Thermal_20261028/VALIDATION.md)에 있습니다. 이 수치를 실제 차량 예측 정확도로 사용하지 않습니다.

실제 Pi에서 관찰된 연구용 이력 수집 화면과 설정 저장 결과는 [STATUS.md](STATUS.md)에 별도로 기록했습니다. GitHub 정리 과정에서 장치를 원격 조작하거나 새 펌웨어를 업로드하지 않았습니다.
