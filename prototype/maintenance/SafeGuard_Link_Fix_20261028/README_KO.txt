SafeGuard Link Fix 20261028 — 실제 장비 확인 전 수정 후보

변경
1. 펌웨어 확인: 동일 포트에서 15초 대기. 실패 시 수신 바이트/잘못된 줄/관측 firmware_id 표시. 다른 펌웨어 허용이나 검사 우회 없음.
2. ESP32/UWB 포트 열기 전에 DTR/RTS=False 지정. OS/드라이버의 순간 신호나 실제 전원 리셋을 완전히 막는다는 보장은 없음.
3. ESP32: 12초 동안 유효 telemetry가 없거나 줄 길이가 초과되면 재연결. 기존 pending/출력 큐 폐기 유지. C++의 통신 손실/MCU 재부팅 시 수동 정지 로직은 수정하지 않음.
4. UWB: 리더 종료 후 3초 간격 재시작, 매번 장치 재탐색. 시작 때 3초 관측하고 DIST가 있으면 쓰기 없음. 무응답이면 CR 두 번 후 3초 관측, dwm>가 확인되고 DIST가 없을 때만 lec 1회 전송. 다른 출력만 있거나 셸 응답이 없으면 임의 토글하지 않음.
5. 설치 시 현재 파일 백업, 18°C→35°C 및 servo80→미지정 복구. 메인/펌웨어 자동 실행 또는 업로드 없음.

한계
- USB 장치가 그대로 열린 상태에서 UWB 출력만 나중에 멎는 경우, lec를 계속 재전송하지 않음. 거리 유효시간 만료 후 UNKNOWN 유지. 원인 진단 필요.
- 정상 출력의 일부 조각이나 느린 보드 응답 때문에 시작 절차가 보수적으로 중단될 수 있음.
- 물리 전원/케이블 불량, 보조배터리 자동 꺼짐, 드라이버 신호는 이 패치만으로 해결 보장 불가.
- UWB 재수신과 ESP32 재연결은 다름. ESP32 통신 손실/재부팅 시 기존 수동 정지 로직 유지. UWB만 복구되면 기존 FSM 판단을 따름.
- firmware_id 검사는 인증/장비 안전 인증이 아님. 서보 준비 보고는 실제 회전 확인이 아님.

검증
소프트웨어 모의 시험 14개 통과: 분할 status, 5초 이후 status, 잘못된 firmware/장치 거부, 무응답 진단, UWB 이미 출력 중/분할 DIST/셸 응답/무응답/알 수 없는 출력/1회 토글 제한, ESP32 재연결 큐 폐기, UWB 재시도 종료.
기존 UWB --self-test 통과. Python 문법 검사 통과.
실물 Pi/ESP32/DWM1001 시험은 아직 수행하지 않음. 전체 C++/펌웨어 통합 시험을 이번 환경에서 다시 수행하지 않았음.

설치
12V 분리, 메인 종료, Pi/USB 전원 유지.
python3 ~/SafeGuard_Link_Fix_20261028/install_fix.py
제공 스냅샷과 설치 파일이 다르면 덮어쓰지 않고 중단.
성공 후 원래 run_control.py로 실행. 시작은 수동 정지.
먼저 12V 없는 상태에서 정지 확인됨/온도 유효/UWB 거리 유효 확인.
PIR은 MCU 부팅 후 60초 준비 시간이 있음.

현장 전 시험 (12V 분리 상태)
- 메인 시작/종료 3회. 매회 정지 확인과 유효 거리/온도 확인. UWB USB를 매번 뽑을 필요 없음.
- UWB USB 1회 재연결: 끊긴 동안 거리 무효, 이후 새 표본으로 복구. 기존 거리 재사용 금지.
- ESP32 USB 1회 재연결: 끊긴 동안 정지 미확인, 복구 후 수동 정지 유지 확인. 감시 자동 재개 여부 확인.
- 반복 재부팅/USB 오류는 sudo journalctl -k -b --since '10 minutes ago'로 기록해 하드웨어 원인 별도 점검.
- 이 시험이 끝나기 전 12V를 연결하거나 부하를 작동시키지 않음.
