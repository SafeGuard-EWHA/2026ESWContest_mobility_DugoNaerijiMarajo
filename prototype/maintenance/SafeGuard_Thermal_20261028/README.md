# SafeGuard 열 추정 통합 패키지 — 2026-10-28

## 완료 범위와 현재 한계

현재 대시보드의 온도 카드에 문헌 기반 열 추정 곡선·35°C 도달 추정·데이터 대기 사유를 추가합니다.
실측 온도는 기존 ESP32 SHT31 경로를 사용합니다. 상태 로그에는 `thermal_observer`가 추가됩니다.
**차량 검증 완료품이 아닌 연구용 구현입니다. 예측을 근거로 한 자동 선제 구동은 활성화하지 않습니다.**
기존 FSM의 보호 조건과 35°C 실측 반응, 전체 정지, UART, 서보 80°는 변경하지 않습니다.
본 패키지 설치만으로 차량 잔류 탑승자 보호 시스템 전체가 검증 완료되는 것은 아닙니다.

## 빠른 설치

먼저 기존 메인을 종료한 상태에서 진행합니다. 현재 사용자는 백업과 35°C 복원을 완료했습니다.
Windows 다운로드 폴더에 ZIP을 저장한 뒤 **Windows 명령 프롬프트**에서:

```bat
scp "%USERPROFILE%\Downloads\SafeGuard_Thermal_20261028.zip" pi@safeguard.local:/home/pi/
```

**Pi 터미널**에서:

```bash
python3 -m zipfile -e ~/SafeGuard_Thermal_20261028.zip ~/
python3 ~/SafeGuard_Thermal_20261028/install.py
```

설치기는 원본 버전 확인 → 임시 복사본 빌드 → C++ 테스트 → 백업 → 파일 교체를 수행합니다.
컴파일러, CMake, nlohmann-json 개발 헤더가 필요합니다. 기존 메인을 빌드한 Pi 환경을 전제로 하며,
없으면 원본을 바꾸기 전에 실패합니다. 인터넷 다운로드나 임의 패키지 설치는 하지 않습니다.
소스가 기준 버전과 다르면 중단하며, 강제 덮어쓰기는 제공하지 않습니다.
Node가 설치되어 있으면 화면 표시 테스트도 실행합니다. 이 패키지의 화면 테스트는 개발 환경에서 별도 통과했습니다.

`INSTALLED`가 출력되면 기존 실행 명령을 사용합니다.

```bash
python3 -u ~/SafeGuard_Software_Stop_20261024/run_control.py --project ~/SafeGuard_Main 2>&1 | tee ~/safeguard_thermal_check.log
```

브라우저용 SSH 터널이 끊겼다면 별도 **Windows 명령 프롬프트**에서:

```bat
ssh -N -L 8080:127.0.0.1:8080 pi@safeguard.local
```

이 창은 열어 두고 `http://127.0.0.1:8080/`을 새로고침합니다. 이미 8080 터널이 열려 있으면 중복 실행하지 않습니다.
ESP32 펌웨어를 다시 업로드할 필요는 없습니다.

## 화면에서 확인할 것

- 시작: `연구용 추정 대기`, 실측 이력 `0 / 600초`부터 수집합니다. 수동 정지 유지 중에도 온도 이력을 수집합니다.
- 연속 10분 수집 후: 최근 온도 추세로 향후 5분 곡선과 기준 도달 시간을 표시합니다.
- 기준을 넘지 않는 계산: `향후 5분 내 도달 추정 없음`. 이는 안전 판정이 아닙니다.
- 온도 끊김, 출처 변경, 시각 역행: 이력을 폐기하고 다시 수집합니다. 멈춘 데이터를 최신으로 재사용하지 않습니다.
- 팬 구동 또는 제어기 피드백 불명: 냉각 개입을 학습한 모델이 아니므로 예측을 중단합니다.
- 급격한 온도 변화: 추세 적합도가 나쁘면 곡선을 보류합니다.
- 외기 22.2–35.6°C 범위의 초기 구간에는 `일사 노출 주차 가정` 곡선을 따로 표시할 수 있습니다.
  **현재 환경의 예측이 아니며**, 외기가 이 범위 밖이면 이 참고 곡선도 표시하지 않습니다.
- 현재와 같은 겨울 환경의 실측 추세 계산에는 `원 연구 범위 밖`을 표시합니다. 해당 차량 정확도는 아직 측정되지 않았습니다.

압축 안의 `preview.html`은 **합성 데이터로 생성한 계산 예시**입니다. 다운로드 후 더블클릭으로 열 수 있으며,
Pi 연결·장치 구동·인터넷 통신을 하지 않습니다. 실제 장치 화면이라고 발표하면 안 됩니다.

## 설치가 바꾸는 것

`src/main.cpp`에 별도의 관측 계산과 JSON 기록을 추가하고, `src/thermal_observer.hpp`를 추가합니다.
`scripts/dashboard.html`의 온도 카드 표시와 `build/safeguard_main`을 업데이트합니다.
`configs/real_navigation_control.json`에는 `thermal.literature_observer_enabled=true`만 추가합니다.
`thermal.enabled=false`, `thermal.calibrated=false`, `risk_temp_c=35`, 기존 서보 각도를 유지합니다.
`src/core.cpp`, 센서 허브, 링크 수정 패키지, ESP32 펌웨어, 배선은 수정하지 않습니다.
기존 `thermal` 필드와 `telemetry.csv`의 `t35_s`는 기존 제어 모델 결과입니다.
새 연구용 결과는 `states.jsonl` / `current_state.json`의 **`thermal_observer`**에서 읽습니다.

## 원상복구

설치 성공 시 `BACKUP`과 `ROLLBACK` 명령이 출력됩니다. 메인 종료 후 출력된 `ROLLBACK` 명령을 그대로 실행합니다.
복구는 설치 전 코드·바이너리·화면·설정을 되돌립니다. 설치 이후 사용자가 수정한 파일이 발견되면 덮어쓰지 않고 중단합니다.
설치 실패 시 교체를 시작하지 않았거나, 교체 중 오류인 경우 백업에서 복원하도록 작성했습니다.
갑작스러운 전원 차단은 소프트웨어 예외 복구 범위 밖이므로 설치 중 전원을 유지하세요.

## 다음 검증과 자동 제어 연결

문헌 출처와 구현 근거는 `METHOD.md`, 검증 기록은 `VALIDATION.md`에 있습니다.
자동 선제 구동을 완성하려면 해당 차량의 독립 데이터로 기준 도달 시간 오차, 특히 늦게 경고하는 오차,
초기 데이터 부족 상황, 팬/창문 개입 후 동작을 검증해야 합니다.
**`calibrated=true`로 이름만 바꾸면 이 모델이 연결되는 구조가 아닙니다.**
관측 결과의 `control_eligible`는 항상 false이고, 별도 모델을 기존 제어 경로에 몰래 끼워 넣지 않았습니다.
현재 연구용 `candidate_early_warning`는 관찰용 조건 표시이며 물리 출력 명령이 아닙니다.
실측 35°C 보호는 기존 탑승·이탈 판정 조건하에서 계속 동작합니다.
