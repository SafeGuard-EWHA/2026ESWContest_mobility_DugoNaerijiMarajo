# SafeGuard 선제 보호 연결 — 2026-10-28

기존 열 추정 설치가 완료된 Pi에 적용하는 후속 패키지입니다. 예측을 보기만 하던 경로를 기존 보호 상태 전이에 연결합니다. ESP32 펌웨어 업로드와 배선 변경은 없습니다.

## 동작

- 위험 기준 35°C, 선제 보호 시간 60초. 실측 35°C 미만이어도 유효한 예측의 도달 시간이 60초 이내이면 기존 THERMAL 상태에서 PROTECTION으로 진입합니다.
- 보호자 이탈 및 탑승 확인/의심 등 기존 상태 전이 조건을 유지합니다. 보호자가 가까운 STANDBY에서 예측만으로 출력을 켜지 않습니다.
- 기존 출력 경로로 팬·부저를 요청하며, 서보는 기존 `servo_protect_deg` 설정을 사용합니다. 설치기는 서보 각도를 바꾸지 않습니다.
- 전체 정지가 최우선이며 시작 시 정지 유지입니다. 예측은 같은 루프에서 계산한 최신 온도와 타임스탬프가 일치할 때만 전달합니다. UART로 예측값을 주입하는 경로는 없습니다.
- 보호 상태 진입 후 팬 때문에 예측이 무효화되거나 온도 입력이 끊겨도 기존 보호 래치를 유지합니다. 전체 정지·기존 보호 해제 절차를 사용합니다.
- 실측 온도 35°C 보호는 예측 이력 부족이나 예측 실패와 무관하게 기존 조건 아래 작동합니다.

## 예측 준비와 한계

기존 최근 600초 이력 및 향후 300초 예측 모델을 그대로 사용합니다. 재시작·온도 수신 중단·팬 개입 후에는 이력 재수집이 필요합니다. 갑작스런 가열 직후 즉시 정확한 예측이 생기는 것은 아닙니다. 현재 온도 자체가 35°C에 도달하면 실측 보호 경로가 우선합니다.

차량 예측 정확도를 검증한 모델이라는 주장은 하지 않습니다. 이번 패키지는 요청된 선제 보호의 기능 연결이며, 기존 문헌 기반 추세 모델의 겨울 외기·일사·차량별 일반화 한계는 남아 있습니다. 예측 활성화와 교정 완료를 혼동하지 않도록 `calibrated=false`를 유지하며, 새 `predictive_control_enabled=true` 설정으로 이 경로를 명시적으로 사용합니다. 기존 미보정 고정 RC 제어는 `thermal.enabled=false` 그대로입니다.

## 설치

1. 전체 정지 → 정지 확인 및 실제 출력 꺼짐 확인 → 실행 창 Ctrl+C.
2. 압축 파일을 Pi 홈 폴더에 복사한 다음:

```bash
python3 -m zipfile -e ~/SafeGuard_Predictive_Control_20261028.zip ~/
python3 ~/SafeGuard_Predictive_Control_20261028/install.py
```

지원되는 기존 소스 해시 확인 → 별도 사본 빌드·테스트 → 백업 → 교체 순서입니다. 버전이 다르면 원본을 덮어쓰지 않습니다. CMake, C++17, nlohmann-json 헤더가 필요합니다. Node가 있으면 화면 테스트도 실행합니다.

성공 메시지 `INSTALLED: 60초 이내 35°C 도달 예측 → 기존 보호 출력` 확인 후:

```bash
python3 -u ~/SafeGuard_Software_Stop_20261024/run_control.py --project ~/SafeGuard_Main 2>&1 | tee ~/safeguard_predictive_control.log
```

항상 정지 유지로 시작합니다. 이력 준비 및 입력 상태 확인 후 감시 재개를 눌러야 자동 보호가 가능합니다. 화면에는 `선제 보호 제어` 표기가 나옵니다. 조기 보호가 발생하면 상태 로그의 진입 이유는 `predicted_temperature_at_risk`입니다. 이후 래치 유지 구간에서는 이유가 바뀔 수 있습니다.

설치기가 출력하는 ROLLBACK 명령으로 정지 상태에서 복원할 수 있습니다. 재설치는 지원 해시에 맞지 않아 거부됩니다. 메인은 자동 시작하지 않습니다.
