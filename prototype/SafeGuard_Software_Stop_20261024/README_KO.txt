SafeGuard 컴퓨터 전체 정지 / 감시 재개 통합 — 0.3.0

이 파일은 공모전 최종 시연 프로그램에 넣을 제어 기능입니다.
기존 SafeGuard_Main에 적용하며, 프로젝트 전체의 실물 통합 완료를 뜻하지는 않습니다.
이전 SafeGuard_BlockA_Control_20261024의 0.2.0 코드를 새로 올리지 말고,
이번 폴더의 SafeGuard_Software_Stop.ino를 사용합니다.

1. 달라지는 동작

컴퓨터 브라우저 → Pi 메인 → 같은 USB 통신 담당 프로그램 → ESP32로 전달됩니다.
메인이 실행 중일 때도 화면의 '전체 정지'를 누를 수 있습니다.
팬·부저: GPIO OFF. 서보: PWM 제어 신호 해제. 정지는 별도 '감시 재개' 전까지 유지합니다.
'감시 재개'는 이전 출력을 바로 켜는 버튼이 아닙니다. 출력 OFF 상태에서 판단을 다시 시작합니다.
메인/ESP32를 다시 켜면 정지 상태부터 시작합니다. 매 실행 후 감시 재개를 눌러 주세요.

화면의 '정지 확인됨'은 해당 정지 요청에 대해 ESP32가 팬·부저 OFF, 서보 신호 해제를
보고했다는 뜻입니다. 팬 회전이나 서보 위치를 직접 측정한 결과는 아닙니다.
컴퓨터/USB/ESP32가 동작해야 하는 소프트웨어 수동 정지이며, 하드웨어 비상정지는 아닙니다.
서보 신호 해제는 서보 전원 차단·제동·안전 각도 복귀가 아닙니다. 기계식 창문 동작은 별도 확인이 필요합니다.

통신이 끊기면 '정지 확인 불가'로 표시합니다. ESP32는 기존 팬·부저 출력 상태를 유지하고
서보 신호를 해제합니다. 통신이 복구되면 메인이 정지 명령을 보내며, 재개는 수동입니다.
명령창 종료나 Ctrl+C를 전체 정지 대신 쓰지 마세요. 먼저 화면에서 전체 정지 → 정지 확인됨을 보세요.

2. A블록 팀원이 할 일 — ESP32에 코드 한 번 올리기

기존 sketch_oct24b.ino 기준 배선을 그대로 사용합니다.
PIR=27 / SHT31 SDA=32, SCL=33 / 팬 2개 제어=25 / 부저=26 / 서보=13.
물리 비상정지 버튼은 연결하지 않습니다. 코드에서도 연결됐다고 표시하지 않습니다.
SHT31은 0x44, 실패하면 0x45를 확인합니다. PIR 준비시간은 부팅 후 60초입니다.

코드 교체와 최초 통신 확인 때는 팬·부저 외부 12V와 서보 외부 5V 출력을 꺼 두고
ESP32 USB만 사용합니다. 이후 A 담당자가 확인한 기존 회로에 출력을 연결합니다.

ZIP을 Windows에서 압축 풀기 → 다음 파일을 Arduino IDE에서 열기:
  firmware\SafeGuard_Software_Stop\SafeGuard_Software_Stop.ino
ArduinoJson 6.21.x 또는 7.x, Adafruit SHT31 Library가 필요합니다.
지금 A 담당자가 사용하던 ESP32 보드 종류와 USB 포트를 선택하고 업로드합니다.
완료 후 시리얼 모니터는 닫고 ESP32 USB를 Pi에 연결합니다.

기존 코드의 독립 AUTO 온도 제어는 이번 코드에서 사용하지 않습니다.
이제 Pi 메인이 판단하고 ESP32가 출력 명령을 실행합니다. 원본 .ino는 originals에 보관했습니다.
A 담당자의 배선이나 코드가 이 기준에서 바뀌었다면 최신 내용을 합친 후 업로드해야 합니다.
ESP32 대상 컴파일/업로드 성공과 실물 출력은 현장에서 확인해야 합니다.

3. 누님이 할 일 — ZIP 보내기와 Pi 설치

다운로드한 ZIP을 C:\SafeGuard_C 안에 넣습니다. 압축파일 이름을 바꾸지 마세요.

[Windows CMD: C:\Users\shinh> 또는 C:\SafeGuard_C>가 보이는 창]
scp C:\SafeGuard_C\SafeGuard_Software_Stop_20261024.zip pi@safeguard.local:/home/pi/
ssh -L 8080:127.0.0.1:8080 pi@safeguard.local

이름 접속이 안 되면 safeguard.local만 '현재 Pi IP'로 바꿉니다.
예전 172.20.10.8이 지금도 같은지는 확인해야 합니다.
ssh 비밀번호를 넣고 pi@safeguard:~ $가 보인 다음 아래 명령을 실행합니다.

[Pi SSH: pi@safeguard:~ $ 창]
unzip -n ~/SafeGuard_Software_Stop_20261024.zip -d ~
python3 ~/SafeGuard_Software_Stop_20261024/install.py --project ~/SafeGuard_Main

설치기는 현재 파일 확인 → 별도 임시 폴더에서 C++ 컴파일/검사 → 백업 → 적용 순서입니다.
INSTALLED가 나와야 완료입니다. 다른 버전/팀원 변경을 발견하면 덮어쓰지 않고 중단합니다.
현재 메인이 돌고 있으면 설치하지 않습니다. 그 메인만 정상 종료한 뒤 다시 실행합니다.
Pi를 재부팅하거나, 다른 팀원의 프로그램·핸드폰 위치 서비스는 종료하지 않습니다.
컴파일에 cmake/g++/nlohmann-json이 없다고 나오면 오류 전문을 보내 주세요.
기존 UWB·카메라·날씨 설정 및 원본 configs/real_navigation.json은 보존합니다.
새 설정파일은 configs/real_navigation_control.json입니다. 출력은 허용하지만 시작 상태는 정지입니다.

4. 실행과 화면 열기

새 ESP32 코드 업로드 및 Pi USB 연결이 끝난 다음, 위 SSH 창에서:
python3 ~/SafeGuard_Software_Stop_20261024/run_control.py --project ~/SafeGuard_Main

실행기는 먼저 CP2102 포트와 새 펌웨어 버전을 확인합니다. FIRMWARE_OK가 보여야 합니다.
잘못된 펌웨어면 메인을 실행하지 않습니다. 이 확인에서 UART 명령은 보내지 않지만
USB 포트를 여는 과정에서 보드가 재부팅될 수 있습니다.

[노트북 Chrome/Edge 주소창]
http://127.0.0.1:8080/

위 ssh -L 창은 닫지 않습니다. 브라우저 화면에 전체 정지 / 감시 재개 버튼이 있습니다.
처음 '수동 정지 유지', '정지 확인됨'을 확인합니다.
외부 출력 전원을 아직 끈 상태로 감시 재개 → 전체 정지를 눌러 응답을 먼저 확인합니다.
UWB 등을 연결하지 않았다면 감시 재개 후 INIT/FAULT는 가능하며, 정지 통신 확인과는 별개입니다.

5. 팬·부저·서보 실물 통합

A 담당자가 기존 회로의 외부 전원을 연결한 뒤 동일 화면에서 확인합니다.
감시 재개는 강제 출력 ON이 아닙니다. 실제 FSM의 보호 조건을 충족해야 켜집니다.
현재 원래 기준은 UWB 5m 초과 10초, 탑승 증거, 실내온도 35도 기준입니다.
본 업데이트는 이 기준과 미완성 mmWave/예측 보정을 임의로 바꾸지 않습니다.
주변 온도가 35도 미만이면 팬·부저가 안 켜지는 것이 곧 고장은 아닙니다.
실제 가열 없이 동작을 보여줄 때는 시험 온도를 명확히 표시하는 시연 절차를 별도로 정해야 합니다.

서보의 보호 시 각도는 자동으로 임의 설정하지 않았습니다. 기본은 신호 해제입니다.
팀원이 부하 없는 서보에서 100도를 사용해도 되는지 확인한 경우에만 다음처럼 설정합니다.
먼저 전체 정지 → 정지 확인됨 → 해당 메인을 Ctrl+C로 종료한 뒤:
python3 ~/SafeGuard_Software_Stop_20261024/set_servo_angle.py --project ~/SafeGuard_Main --angle 100
python3 ~/SafeGuard_Software_Stop_20261024/run_control.py --project ~/SafeGuard_Main

다른 각도가 필요하면 마지막 숫자를 팀원이 확인한 45~135 범위 값으로 바꿉니다.
이 값은 서보 요청 각도이며, 창문이 몇 cm 열리는지의 보정값이 아닙니다.
보호 상태에서 팬·부저·설정한 서보가 동작함 → 전체 정지 → 정지 확인됨과 실물 정지를 함께 확인합니다.
정지 중 감시 재개를 누르지 않고 기다려도 다시 작동하지 않아야 합니다.

6. 다음 날 / 시연 날

기존 핫스팟으로 Pi·노트북 연결 → ESP32 및 사용할 센서 연결.
아이폰 날씨 위치를 쓸 때는 기존 https://safeguard.local:8443/ 페이지에서 전달 시작.
Windows에서 위 ssh -L 명령 → Pi에서 run_control.py → 노트북 http://127.0.0.1:8080/.
코드 업로드와 설치는 매번 할 필요 없습니다. 매 실행 후 정지 확인 → 감시 재개만 합니다.
끝낼 때는 전체 정지 확인 → 해당 메인 Ctrl+C → SSH창 종료. Pi 전체 종료는 팀 작업과 협의합니다.
