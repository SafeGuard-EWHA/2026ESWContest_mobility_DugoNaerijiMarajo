# 공동 작업 절차

1. 기존 저장소의 파일과 브랜치를 확인한 뒤 초기 기준본을 별도 브랜치로 올립니다. 기존 코드는 강제 덮어쓰기하지 않습니다.
2. 기능별로 `fix/servo`, `fix/uwb`, `docs/demo` 등의 브랜치에서 작업합니다.
3. PR에 문제, 변경 파일, 실행한 테스트, 실제 장치 확인 여부를 적습니다.
4. ESP32 펌웨어 변경 시 `.ino`를 저장하고, 마지막 실제 업로드 파일·보드 패키지 버전을 남깁니다.
5. Pi에 배포할 때 적용 커밋과 설정을 기록하고, 전체 정지 확인 후 교체합니다. GitHub 업로드와 Pi 배포는 별개입니다.
6. 시연 임시 설정은 기준 설정과 구분합니다. 촬영 전 35°C 복구를 실제 실행 화면/설정으로 확인합니다.

## 공개 금지 파일

Wi-Fi 비밀번호, API/접근 토큰, TLS 개인키, 현재 위치 JSON, 원시 위치 로그는 커밋하지 않습니다. `.gitignore`는 이미 추적 중인 파일을 제거하지 않으므로 PR 변경 파일을 직접 확인합니다.

## 코드 선택 기준

현재 실행 소스는 `SafeGuard_Main`입니다. `maintenance`, `patch`, `originals` 안 파일은 이력·재현 비교용입니다. 최신 서보 수정은 담당자가 별도로 병합해야 합니다. 기존 설치 스크립트는 대상 버전이 일치할 때만 사용합니다.
