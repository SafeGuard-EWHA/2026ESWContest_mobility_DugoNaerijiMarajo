# 소비전력 측정 계획 (2차 컨설팅 반영)

컨설팅 의견: "12V 입력측 전류 측정과 USB 인라인 전력계를 함께 쓰면 충분하다. 측정 경계, 측정 시간, 상태별 평균전력과
에너지 계산 방법을 같게 유지할 것. 짧은 Wake-up 순간의 Peak까지 볼 때만 전력 로거를 추가한다."

## 1. 측정 경계 (3곳, 바꾸지 않는다)

| 경계 | 계측기 | 연결 위치 | 포함되는 부품 |
|---|---|---|---|
| ① Pi 5V 입력 | USB-C 인라인 전력계 | Pi 27W 어댑터 ↔ Pi 5 사이 | Pi 5, 카메라, 레이더(USB), UWB 차량측(USB), ESP32(USB 전원일 때) |
| ② 12V 구동 입력 | 테스터기 DM-1010 **직렬**, 10A 단자 | 12V 입력선, 퓨즈 앞 | 팬, 부저, 서보(컨버터 거쳐) |
| ③ 보호자 UWB | USB-A 인라인 전력계 | 보조배터리 ↔ DWM1001 | 보호자측 UWB 노드 |

- 레이더, 카메라, ESP32가 Pi USB에서 전원을 받으면 ①에 모두 들어간다. 부품별로 나누지 않고 **경계별로** 적는다.
- 테스터기 전류 측정은 선을 끊고 직렬로 넣어야 한다 (병렬로 대면 단락). 측정 전 10A 단자, 퓨즈 확인.

## 2. 상태별 측정 (각 상태 60초)

| 상태 | 무엇이 켜져 있나 |
|---|---|
| STANDBY | Pi, UWB, ESP32 기본 수집만 |
| PRIMARY | + 카메라 프레임 차분 처리 |
| MMWAVE | + 레이더 데이터 수신, 해석 |
| THERMAL | + 온도 예측 계산 |
| PROTECTION | + 팬, 부저 구동 (②가 크게 바뀜) |

1. 상태에 들어가고 **10초 기다린 뒤** 60초 동안 10초마다 전압(V), 전류(A)를 적는다 (6번). 전력계 화면을 휴대폰으로 동영상 촬영해 나중에 읽어도 된다.
2. 평균 전력 P = 평균 V × 평균 A. 경계 ①②③을 따로 적고 합계도 적는다.
3. 같은 측정을 **3번** 반복한다.

## 3. All-on 대 Event-driven 비교 (3쌍)

- 같은 시나리오(예: 이탈 → 감지 → 보호까지 10분)를 두 방식으로 각각 돌린다.
  - All-on: 처음부터 모든 감지, 처리를 켠 채로
  - Event-driven: 실제 FSM 순서대로 필요한 단계만
- 에너지 E(Wh) = Σ (상태별 평균 전력 W × 그 상태에 머문 시간 s) / 3600
- 절감률 = (E_all-on − E_event) / E_all-on × 100. 3쌍의 평균과 범위를 적는다.

**정직하게 적을 점**: 레이더는 한 번 `sensorStop`하면 USB를 다시 꽂아야 켜지므로 지금은 계속 전원이 들어가 있다.
그래서 절감은 "레이더 데이터 처리와 Pi 연산을 필요할 때만 한다"는 범위에서만 주장한다 (완전 전원 차단 아님).
