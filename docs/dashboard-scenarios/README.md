# SafeGuard 상황별 대시보드 캡처

실제 개발·시연 과정에서 팀원이 공유한 화면을 **운영 시나리오 순서**로 정리했습니다.
서로 다른 실행 시점과 개발 버전의 캡처이며, 한 번의 연속 실행 기록은 아닙니다. 화면의 수치와 상태는 원본 그대로 보존했습니다.

[저장소 첫 화면](../../README.md) · [시연 동영상](https://www.youtube.com/watch?v=aBB1S666mp4)

## 1. 시작 전 — 수동 정지 확인

![수동 정지 유지와 ESP32 정지 확인](images/01-manual-stop.png)

**현재 판단은 ‘수동 정지 유지’, 운영 제어는 ‘정지 확인됨’입니다.**
ESP32가 팬·부저 OFF와 서보 신호 해제를 보고한 상태입니다. 감시를 시작할 때는 ‘감시 재개’를 요청합니다. 제어기의 보고와 실물의 정지 여부는 구분합니다.

## 2. 감시 재개 — 보호자 근거리 대기

![보호자 근거리 조건 충족과 대기 상태](images/02-standby.png)

**보호자가 가까이 있어 ‘대기’ 상태를 유지합니다.**
‘보호자 이탈 조건 미충족’, ‘근거리 조건 충족’, ‘감시 중’을 함께 확인할 수 있습니다. 이탈 판단 기준은 화면에 표시된 거리 5m / 유지 10초입니다.

## 3. 보호자 이탈·탑승 의심 — 열위험 판단 진입

![이탈 조건 충족과 탑승 의심에 따른 온도 위험 확인](images/03-away-thermal.png)

**‘이탈 조건 충족’과 ‘탑승 의심’ 상태에서 ‘온도 위험 확인’ 단계로 진행한 화면입니다.**
이 캡처에는 ‘온도 입력만 사용 · 예측 사용 불가’가 표시되어 있습니다. 따라서 예측이 완료되었거나 팬이 작동한 장면으로 해석하지 않습니다.

탐지 흐름은 **UWB 이탈 → PIR 또는 카메라 1차 탐지 → mmWave 추가 확인 → 열위험 판단**입니다.
mmWave 입력 이상 시에는 PIR과 카메라의 동시 증거를 사용하는 대체 경로가 있습니다. 이 화면의 ‘탑승 의심’만으로 mmWave의 정상 확인 성공을 단정할 수는 없습니다.

## 4. 열 예측 — 향후 5분 내 도달 추정 없음

![35도 기준선 아래의 온도 예측 곡선](images/04-no-crossing-forecast.png)

**예측 곡선이 35°C 기준선 아래에 있어 ‘향후 5분 내 도달 추정 없음’으로 표시됩니다.**
‘향후 5분’은 예측 범위이며, 5분 뒤 반드시 35°C가 된다는 뜻이 아닙니다. 최근 600초는 예측에 필요한 온도 이력 수집 구간이며, 시간이 지났다는 이유만으로 보호 출력이 켜지는 것은 아닙니다.

## 5. 선제 보호 — 영상으로 확인하는 단계

보호자 이탈과 탑승 증거가 충족되고 감시 중일 때, 유효한 예측에서 **35°C 도달 예상 시간이 60초 이내**이면 팬·부저·서보의 보호 출력을 요청합니다. 현재 온도가 이미 35°C 이상인 직접 보호 조건도 별도로 확인합니다.

이 단계의 실제 동작은 [팀 시연영상](https://www.youtube.com/watch?v=aBB1S666mp4)으로 연결합니다.
이번 캡처 모음에서는 **35°C 미만 + 도달 예상 60초 이내 + 보호 출력 상태**가 함께 보이는 원본을 확보하지 못했으므로, 다른 상태의 화면을 성공 장면으로 대체하지 않았습니다. 촬영용 온도 입력을 사용한 시연과 실차 온도 실측은 구분합니다.

## 6. 종료 — 전체 정지와 정지 확인

시연을 마치면 ‘전체 정지’를 요청하고 **‘수동 정지 유지’와 ‘정지 확인됨’**을 확인합니다.
위 [1번 정지 화면](#1-시작-전--수동-정지-확인)은 이때 확인할 표시의 예시입니다. 해당 이미지를 시연 종료 직후의 연속 캡처로 주장하지 않습니다.

## 별도 상황 A. 일부 센서 입력 WAITING

![UWB 수신과 PIR 카메라 mmWave 입력 대기](images/a1-sensor-waiting.png)

UWB는 0.24m로 수신되지만 PIR·카메라·mmWave는 WAITING / 입력 사용 불가입니다.
**입력을 사용할 수 없는 상태와 탑승자가 없다는 판단은 다릅니다.** mmWave 영역은 존재 증거를 표시하며 호흡이나 생체 상태를 판정하는 화면이 아닙니다.

## 별도 상황 B. ESP32 정지 확인 불가

![ESP32 연결 확인 필요와 정지 미확인](images/a2-controller-unavailable.png)

화면은 ‘수동 정지 유지’이지만, **‘ESP32 연결 확인 필요 · 정지 완료를 확인하지 못함’**이 표시됩니다.
정지 요청을 유지하는 것과 ESP32의 정지 보고를 받은 것을 구분해 보여주는 사례입니다.

## 별도 상황 C. 대시보드 상태 수신 중단

![연결 대기와 전체 WAITING 화면](images/a3-dashboard-disconnected.png)

대시보드가 최신 제어기 상태를 받지 못해 전체 항목을 WAITING으로 표시합니다.
이 화면만으로 모든 소자가 꺼졌거나 센서가 각각 고장 났다고 판단할 수는 없습니다. 메인 프로세스와 네트워크·SSH 터널 연결을 확인하는 상황입니다.
